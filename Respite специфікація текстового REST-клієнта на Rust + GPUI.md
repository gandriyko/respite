# Respite: специфікація текстового REST-клієнта на Rust + GPUI

Nov 11, 2026 · @Andrew

## Огляд і цілі

Десктопний REST-клієнт на Rust і GPUI, у якому запити живуть як звичайний текст у файлах `.http`. Це не Postman із формами, а редактор у дусі [REST Client для VS Code](https://marketplace.visualstudio.com/items?itemName=humao.rest-client) та [HTTP Client у JetBrains](https://www.jetbrains.com/help/idea/http-client-in-product-code-editor.html). Робочий цикл: написав запит → Cmd+Enter → бачиш відповідь праворуч.

**Цілі**

- Один файл тримає багато запитів, розділених `###`. Синтаксис сумісний з VS Code REST Client і JetBrains HTTP Client, тож наявні файли `.http` / `.rest` відкриваються без змін.
- Миттєва навігація: між файлами (бокова панель і швидкий пошук) і між запитами всередині файлу (дерево, пошук за назвою, стрибок до сусіднього запиту).
- Розділений екран: редактор із підсвіткою зліва, результат справа.
- Автодоповнення як в IDE: методи, заголовки, значення `Content-Type` / `Accept`, змінні, середовища.
- Нативна швидкість: холодний старт < 300 мс, відкриття файлу на 5 000 рядків < 50 мс, введення без затримок (GPU-рендер GPUI).

**Не-цілі (у першій версії)**

- Візуальні форми для збирання запитів і колекції в базі даних: джерело правди тільки файли на диску.
- Хмарна синхронізація та командні робочі простори: файли версіонуються через git.
- gRPC і WebSocket: розглядаються у фазі 3.

**Терміни**

- *Робоча тека* — коренева директорія проєкту, яку відкриває користувач.
- *Файл запитів* — файл `.http` або `.rest`.
- *Блок запиту* — фрагмент файлу між двома роздільниками `###`.

## Макет інтерфейсу

&#91;embedded content: вікно застосунку · 3 зони\]

Ліворуч — дерево файлів, де кожен файл розгортається у список своїх запитів. Посередині — редактор із виділеним активним блоком (лише текст, без кнопок і статусів у рядках). Праворуч — відповідь для блоку під курсором. Вибір середовища завжди на виду в верхньому правому куті. Бокову панель і панель відповіді можна сховати (Cmd+B, Cmd+J), а роздільники перетягуються.

## Формат файлу .http

Формат беремо як перетин синтаксисів VS Code і JetBrains, плюс найкорисніше з обох. Там, де вони розходяться, пріоритет за поведінкою VS Code REST Client. Розширення: `.http`, `.rest`. Кодування UTF-8, кінці рядків LF або CRLF.

### Структура блоку запиту

```http
### Створити користувача            ← роздільник + необов'язкова назва
# @name createUser                       ← доступне для посилань
# @timeout 10 s                          ← директиви
POST {{baseUrl}}/users?notify=true HTTP/1.1
Content-Type: application/json
Authorization: Bearer {{token}}

{
  "id": "{{$uuid}}",
  "name": "Аня"
}
```

Правила розбору:

1. **Роздільник.** Рядок, що починається з `###` (три або більше `#`). Текст після нього — людська назва блоку (показується в дереві). Перший блок може не мати роздільника.
2. **Коментарі.** Рядки, що починаються з `#` або `//`, до рядка запиту. Коментар виду `# @слово значення` — директива (таблиця нижче).
3. **Рядок запиту.** `МЕТОД URL [HTTP-версія]`. Якщо метод пропущено, це `GET`. Дозволені власні методи великими літерами (`PURGE`). Версія: `HTTP/1.1`, `HTTP/2`.
4. **Багаторядковий query.** Наступні рядки з відступом, що починаються з `?` або `&`, доклеїваються до URL.
5. **Заголовки.** `Назва: значення`, один на рядок, до першого порожнього рядка.
6. **Тіло.** Усе після порожнього рядка до наступного `###`, скрипта `> {%` чи перенаправлення `>>`. Кінцеві порожні рядки обрізаються.

### Тіло з файлу, multipart, form

```http
### Тіло цілком з файлу
POST {{baseUrl}}/import
Content-Type: application/json

< ./data/import.json

### Файл з підстановкою змінних всередині
POST {{baseUrl}}/import
Content-Type: application/json

<@ ./data/template.json

### Multipart
POST {{baseUrl}}/upload
Content-Type: multipart/form-data; boundary=WebBoundary

--WebBoundary
Content-Disposition: form-data; name="title"

Звіт
--WebBoundary
Content-Disposition: form-data; name="file"; filename="report.pdf"
Content-Type: application/pdf

< ./report.pdf
--WebBoundary--

### Form URL-encoded (багаторядково)
POST {{baseUrl}}/login
Content-Type: application/x-www-form-urlencoded

user=anya
&password={{password}}
```

### GraphQL

Як у VS Code: заголовок `X-Request-Type: GraphQL` (або метод `GRAPHQL` як у JetBrains). Тіло — запит, потім порожній рядок і JSON змінних. Клієнт сам загортає це в `{"query":…,"variables":…}`.

### Директиви запиту

| Директива | Дія | Джерело |
| --- | --- | --- |
| `# @name <id>` | Ім'я для посилань і пошуку | обидва |
| `# @prompt <var> [опис]` | Запитати значення перед відправкою (паролі приховані) | VS Code |
| `# @note` | Підтвердження перед відправкою (небезпечні запити) | VS Code |
| `# @no-redirect` | Не йти за 3xx | обидва |
| `# @no-cookie-jar` | Не читати і не зберігати cookies | обидва |
| `# @no-log` | Не писати в історію (секрети) | JetBrains |
| `# @no-auto-encoding` | Не кодувати URL автоматично | JetBrains |
| `# @timeout <n> [ms\|s\|m]` | Таймаут відповіді | JetBrains |
| `# @connection-timeout <n>` | Таймаут з'єднання | JetBrains |
| `# @insecure` | Не перевіряти TLS-сертифікат | нова |

### Перенаправлення відповіді у файл

`>> ./out/user.json` зберігає тіло відповіді (з суфіксом, якщо файл уже є), `>>! …` перезаписує. Синтаксис JetBrains.

### Імпорт і експорт

- **Вставка cURL.** Вставлена команда `curl …` автоматично конвертується в блок запиту; оригінал лишається коментарем вище (як у JetBrains). Ctrl+Z відкочує конвертацію.
- **Копіювати як cURL.** Дія над блоком з уже підставленими змінними.
- **Генерація коду (фаза 2).** Фрагмент для `reqwest`, Python `requests`, JS `fetch`, як «Generate Code Snippet» у VS Code.
- **Імпорт Postman (фаза 2).** Колекція v2.1 → `.http` + `respite-<env>.json` (по файлу на середовище).

## Змінні

Усі змінні підставляються через `{{ім'я}}` у URL, заголовках і тілі. Невизначена змінна підкреслюється червоним у редакторі, а перед відправкою з'являється попередження (відправити як є / скасувати).

### Пріоритет (вищий перекриває нижчий)

1. **Prompt** — введене користувачем через `# @prompt`.
2. **Змінні сесії** — встановлені скриптом `client.global.set()` (фаза 2).
3. **Файлові** — `@ім'я = значення` у файлі `.http`.
4. **Приватне середовище** — `respite-<env>.private.json`.
5. **Середовище** — `respite-<env>.json`.
6. **Спільні** — `respite.json` / `respite.private.json`.

Динамічні (`{{$…}}`) і посилання на відповіді (`{{ім'я.response…}}`) мають власний синтаксис, тож не конфліктують.

### Файлові змінні

```http
@host = api.example.com
@baseUrl = https://{{host}}/v1
@contentType = application/json

### Список
GET {{baseUrl}}/users
Accept: {{contentType}}
```

Значення може посилатися на інші змінні. Циклічні посилання — помилка діагностики.

### Файли середовищ

Власний формат Respite: один плаский JSON-файл на середовище. Середовища лежать у репозиторії, а не в налаштуваннях редактора. Файли JetBrains (`http-client.env.json`, `rest-client.env.json`) не читаються.

| Файл | Що містить |
|---|---|
| `respite.json` | спільне для всіх середовищ (`$shared`) |
| `respite-<env>.json` | середовище `<env>` |
| `respite-<env>.private.json` | секрети середовища `<env>` |
| `respite.private.json` | спільні секрети |

```json
// respite-dev.json
{ "host": "localhost:8080", "token": "dev-token" }
```

Файли шукаються в усіх теках від кореня проєкту до теки файлу `.http` і зливаються (деталі нижче). Корінь — тека проєкту з бічної панелі, що містить файл; для файлу поза проєктами (і в CLI) — найближча тека з `.git` / `.respite`, тека колекцій `~/.config/respite` або тека самого файлу. Домашня тека коренем не буває: її `.respite` — тека даних застосунку. Приватні файли `*.private.json` пропонується додати до `.gitignore`.

У випадайці середовищ є «Create respite-<env>.json in …» для кореня проєкту (діє на весь проєкт) і для теки поточного файлу (лише на неї та глибше).

Активне середовище обирається в випадаючому списку над редактором («Run with» у JetBrains) або через Cmd+Alt+E. Вибір запам'ятовується на рівні робочої теки. Варіант «Без середовища» завжди є. Запити на середовище з назвою `prod*` показують червону плашку (налаштовується).

#### Скільки може бути файлів середовищ

У кожній теці може бути по файлу на середовище (публічний і приватний) плюс спільні `respite.json` / `respite.private.json`. Таких тек у проєкті може бути скільки завгодно, і для кожного файлу `.http` вони зливаються. Це потрібно для монорепозиторіїв, де у кожного сервісу свій `host`.

```text
workspace/
├── respite.json                  ← спільне для всіх середовищ: apiVersion
├── respite-dev.json              ← dev; так само respite-staging.json, respite-prod.json
├── respite-dev.private.json      ← особисті токени для всіх
├── users/
│   ├── respite-dev.json          ← перекриває host для users-сервісу
│   └── users.http
└── billing/
    ├── respite-dev.private.json  ← ключ Stripe лише тут
    └── invoices.http
```

**Порядок злиття для `billing/invoices.http`** з активним `dev` (пізніший перекриває раніший, на рівні ключа):

1. Спільні `respite.json` / `respite.private.json` з усіх тек за тим самим порядком, що й нижче.
2. `workspace/respite-dev.json`.
3. `workspace/respite-dev.private.json`.
4. `billing/respite-dev.json` (якщо є).
5. `billing/respite-dev.private.json`.

Тобто теки йдуть від кореня до теки файлу, а всередині однієї теки приватний файл перекриває публічний. Злиття неглибоке (на рівні ключів), окрім службових об'єктів на кшталт `SSLConfiguration`, які зливаються глибоко.

**Список середовищ** у випадайці — об'єднання імен з усіх файлів ланцюжка поточного файлу `.http`. Середовище, визначене лише в приватному файлі (напр. особисте `respite-local-anya.private.json`), теж з'являється.

**Додаткові файли поза ланцюжком:**

- У налаштуваннях робочої теки `.respite/settings.json` — ключ `"env": { "files": ["~/secrets/respite-prod.private.json"] }`: додаються після ланцюжка (найвищий пріоритет). Ім'я файлу мусить мати той самий формат, бо саме воно задає середовище; файл з іншою назвою — помилка файлу середовища. Зручно, щоб тримати секрети поза репозиторієм або ділити їх між проєктами.
- CLI / MCP: `--env-file шлях` (можна кілька разів), теж над ланцюжком, з тими самими вимогами до імені.
- Імпорт (Postman, Insomnia, OpenAPI, Bruno) пише `respite-<env>.json` / `respite-<env>.private.json`; наявні середовища не перезаписуються (нове отримує ім'я `dev-2` тощо).

**Помилки та інструменти:**

- Невалідний JSON у файлі середовища — діагностика в цьому файлі і попередження в рядку стану; злиття йде без нього.
- Наведення на `{{host}}` показує кінцеве значення і всі перекриті (закреслені) з файлами-джерелами.
- Команда «Показати злите середовище» та `respite env show dev --explain` виводять таблицю змінна → значення → файл.
- Для файлів середовищ є JSON-схема: автодоповнення імен змінних, вже використаних у `.http`, і попередження про секрет (схоже на токен значення) у публічному файлі.

### Динамічні змінні

| Змінна | Значення |
| --- | --- |
| `{{$uuid}}`, `{{$guid}}` | UUID v4 |
| `{{$randomInt [min max]}}` | Ціле число, за замовчуванням 0–1000 |
| `{{$timestamp [зсув одиниця]}}` | Unix-час у секундах, напр. `{{$timestamp -1 d}}` |
| `{{$isoTimestamp}}` | ISO 8601 у UTC |
| `{{$datetime rfc1123\|iso8601\|"формат" [зсув]}}` | Дата в UTC |
| `{{$localDatetime …}}` | Те саме у локальному часі |
| `{{$processEnv [%]ІМ'Я}}` | Змінна оточення ОС |
| `{{$dotenv [%]ІМ'Я}}` | Значення з `.env` поруч із файлом |
| `{{$random.alphanumeric(n)}}`, `{{$random.email}}` тощо | Випадкові дані (фаза 2) |

### Значення з інших відповідей

Як у VS Code: `{{ім'я.(request|response).(headers|body).шлях}}`. Для JSON шлях — JSONPath (`$.data.token`), для XML — XPath, `*` — все тіло.

```http
# @name login
POST {{baseUrl}}/auth
Content-Type: application/json

{ "user": "anya", "password": "{{password}}" }

###
@token = {{login.response.body.$.access_token}}

GET {{baseUrl}}/me
Authorization: Bearer {{token}}
```

Якщо запит `login` ще не виконувався, клієнт автоматично виконує його спершу в тому самому середовищі. Ланцюжки розв'язуються рекурсивно, цикли — помилка діагностики. У панелі відповіді видно, які запити виконалися по дорозі. Вимикається налаштуванням \`request.auto\_run\_dependencies\`. Останні відповіді іменованих запитів кешуються в пам'яті та на диску в межах робочої теки.

### Підказки в редакторі

- Наведення на `{{змінну}}` показує її значення та джерело (файл, середовище, відповідь). Секрети з приватного середовища маскуються `••••`.
- Cmd+клік / F12 — перехід до місця визначення (рядок `@var`, ключ у файлі середовища або запит `# @name`).
- Shift+F12 — усі використання змінної у файлі; F2 — перейменувати.

## Виконання запитів

Cmd+Enter (Ctrl+Enter на Linux/Windows) виконує блок, у якому стоїть курсор. Відповідь відкривається в правій панелі без втрати фокусу в редакторі.

### Способи запуску

| Дія | Що виконується |
| --- | --- |
| Cmd+Enter | Блок під курсором |
| Кнопка «▶ Run» у заголовку панелі відповіді | Блок під курсором |
| Cmd+Shift+Enter | Усі блоки файлу по черзі |
| Cmd+Alt+Enter | Виділені блоки |
| Cmd+Alt+L | Повторити останній запит з будь-якого місця |
| Esc / Cmd+. | Скасувати активний запит |

### Конвеєр виконання

1. **Визначити блок** за позицією курсора в останньому AST.
2. **Зібрати prompt-змінні та підтвердження** (`# @prompt`, `# @note`, середовище prod) — одним діалогом.
3. **Розв'язати залежності** від інших запитів (`{{login.response…}}`); якщо відповіді ще немає — автоматично виконати їх спершу.
4. **Підставити змінні**, закодувати URL, прочитати файли `<`.
5. **Pre-request скрипт** `< {% %}` (фаза 2).
6. **Відправити** через HTTP-шар із таймаутами, редіректами, cookie jar, проксі.
7. **Прийняти відповідь потоком**: показувати статус і заголовки одразу, тіло — по мірі надходження.
8. **Response handler** `> {% %}` (фаза 2), `>>` — запис у файл.
9. **Зберегти** відповідь у кеш іменованих запитів і в історію.

### Стан у редакторі

- Редактор лишається чистим текстом: ні кнопок запуску, ні статусів у рядках (кнопки ▶ у gutter, inlay-статус і CodeLens спробували й прибрали — заважали читати й редагувати).
- Активний блок позначає смужка в gutter. Стан запиту — у панелі відповіді (`Running…`, «▶ Run» стає «◼ Stop») і біля запиту в дереві сайдбару (код статусу).
- Під час пакетного виконання права панель показує список запитів із статусами; крок можна зупинити на першій помилці (налаштування).
- Довгі запити не блокують UI: можна редагувати та запускати інші блоки паралельно.

### Історія

- Кожне виконання зберігається в `~/.respite/history/<назва проєкту>/` (фактичний запит після підстановки + відповідь), а не в репозиторії. Назва проєкту — ім'я кореневої теки робочого простору. Якщо два різні шляхи мають однакове ім'я, додається короткий хеш шляху (\`api-7f3c\`); відповідність зберігається в \`\~/.respite/projects.json\`. Там само лежить кеш відповідей іменованих запитів і cookie jar. За замовчуванням останні 50 на блок і 500 загалом.
- Файли `.http` клієнт не змінює (як «фізичні файли» у JetBrains).
- Вікно історії (Cmd+Y): список з фільтром, повтор запиту, порівняння двох відповідей у diff.
- `# @no-log` і заголовки зі списку чутливих (`Authorization`, `Cookie`, `X-Api-Key`) маскуються в історії.

### Cookies, редіректи, мережа

- Cookie jar на робочу теку і середовище, зберігається між запусками; команда «Очистити cookies».
- Редіректи: до 10, ланцюжок видно у вкладці Timeline.
- Проксі з `HTTP(S)_PROXY` / `NO_PROXY` або налаштувань; клієнтські сертифікати (mTLS) і власний CA — у файлі середовища в ключі `SSLConfiguration` (як у JetBrains).
- Авторизація-скорочення: `Authorization: Basic user pass` кодується в Base64 автоматично (як у VS Code); `Digest` — у фазі 2.

## Панель відповіді

Права панель показує відповідь блоку, на якому стоїть курсор (синхронізація за курсором вимикається кнопкою «Закріпити», щоб закріпити одну відповідь). Якщо блок ще не виконувався, панель показує підказку «Cmd+Enter — відправити».

### Шапка

Рядок стану: `200 OK` (колір за класом) · час · розмір · HTTP-версія · час виконання. Праворуч — навігація по історії цього блоку (‹ 3/12 ›), кнопки «Копіювати тіло», «Зберегти у файл», «Порівняти з попередньою».

### Вкладки

| Вкладка | Вміст |
| --- | --- |
| Body | Тіло з автоформатуванням і підсвіткою за `Content-Type` |
| Headers | Таблиця заголовків відповіді |
| Cookies | Отримані cookies з атрибутами |
| Request | Фактично відправлений запит після підстановки змінних |
| Timeline | DNS, TCP, TLS, TTFB, завантаження; ланцюжок редіректів |
| Tests | Результати `client.test` (фаза 2) |

### Тіло за типом

- **JSON** — форматований, згортання вузлів, фільтр JSONPath у полі внизу (`$.items[*].id`), копіювання шляху до вузла за правим кліком (зручно для `{{req.response.body.$…}}`).
- **XML / HTML** — форматований текст із підсвіткою; HTML без рендеру (в GPUI немає веб-двигуна).
- **Зображення** (png, jpeg, gif, webp, svg) — перегляд через `img()` GPUI.
- **Текст** — як є; **бінарне** — розмір, тип і кнопка «Зберегти».
- **Сирий режим** — перемикач Pretty / Raw.
- Декодування gzip / br / deflate і кодування з `charset` — автоматично.

### Великі відповіді

- Тіло читається потоком; понад 10 МБ форматування вимикається, понад 100 МБ — тільки збереження у файл (пороги налаштовуються).
- Відображення — віртуалізований список рядків (`uniform_list` GPUI), тож прокрутка не залежить від розміру.
- Пошук у відповіді: Cmd+F, коли фокус у панелі.

### Розташування

Роздільник між редактором і панеллю перетягується (за замовчуванням 55 / 45). Cmd+\\ перемикає вертикальне / горизонтальне розділення, Cmd+J ховає або показує панель.

## Редактор і навігація

Редактор — це повноцінний кодовий редактор із семантикою формату `.http`: він знає, де метод, URL, заголовок чи тіло, і підлаштовує під це підсвітку, підказки та дії.

### Підсвітка синтаксису

- Граматика tree-sitter для `.http` (база: відкрита `tree-sitter-http`, розширена директивами та `>>`). Так само підсвічує і Zed.
- Ролі підсвітки: роздільник і назва, коментар, директива, метод, URL (схема, хост, шлях, query-ключ і значення), назва та значення заголовка, змінна `{{…}}`, динамічна змінна, посилання на файл `<`.
- **Вкладені мови в тілі** (injections) за `Content-Type`: JSON, XML, GraphQL, form-urlencoded; JavaScript у `{% %}`.
- Теми: світла і темна з коробки, формат теми — JSON у стилі Zed.
- Активний блок запиту ледь виділяється фоном, щоб було видно, що саме відправить Cmd+Enter.

### Автодоповнення

Запускається автоматично під час набору та за Ctrl+Space. Нечіткий пошук (`ct` → `Content-Type`), спочатку — нещодавно використані в цій робочій теці.

| Контекст | Що пропонується |
| --- | --- |
| Початок рядка запиту | Методи GET, POST, PUT, PATCH, DELETE, HEAD, OPTIONS + власні з налаштувань |
| Після методу | `{{baseUrl}}`-подібні змінні, URL з інших запитів файлу та історії |
| Кінець URL | `HTTP/1.1`, `HTTP/2` |
| Назва заголовка | Стандартні заголовки запиту (IANA) з коротким описом; вже наявні в блоці відсуваються вниз |
| Значення `Content-Type`, `Accept` | MIME-типи: `application/json`, `application/xml`, `text/plain`, `multipart/form-data; boundary=…`, `application/x-www-form-urlencoded` тощо; для `Accept` також `*/*` і q-ваги |
| Значення `Authorization` | ` Bearer  `, ` Basic  `, ` Digest  ` + змінні з назвою `*token*` |
| Значення інших заголовків | `Accept-Encoding` (gzip, br, deflate), `Cache-Control`, `Connection`, `Accept-Language`, `Content-Encoding` |
| Всередині `{{` | Змінні всіх рівнів зі значенням і джерелом; після `$` — динамічні; після `ім'я.` — `response.body.$…` з ключами з останньої відповіді |
| Після `# @` | Директиви з описом |
| Після ` <  ` або ` >>  ` | Шляхи файлів відносно файлу `.http` |
| JSON-тіло | Закривання дужок і лапок; у фазі 2 — ключі з OpenAPI-схеми |

Шаблони (live templates JetBrains): `gtr` → GET-запит, `ptr` → POST з JSON, `mptr` → multipart, `fptr` → form. Розгортаються через Tab, із таб-стопами по полях.

### Діагностика (підкреслення на льоту)

- Невизначена змінна або запит у `{{ім'я.response…}}`.
- Невалідний JSON у тілі при `Content-Type: application/json`.
- Дубльовані `# @name`, невідома директива, неіснуючий файл після `<`.
- Заголовок без `:`, відсутній boundary у multipart.
- Швидкі виправлення (Cmd+.): створити змінну в файлі або в активному середовищі, додати `Content-Type`.

### Навігація між файлами

- **Бокова панель** — дерево робочої теки, де показано тільки `.http`, `.rest` і файли середовищ `respite*.json` (фільтр вимикається). Файл розгортається як випадаючий список своїх запитів: метод кольоровою позначкою + назва (або URL, якщо назви немає) + статус останнього виконання. Клік — стрибок до запиту; подвійний клік — стрибок + виконання.
- **Cmd+P** — швидкий пошук файлу (нечіткий, як у Zed).
- **Ctrl+Tab** — перемикання між нещодавніми файлами; вкладки відкритих файлів над редактором.
- **Cmd+B** — сховати / показати бокову панель.
- Файли перечитуються при зміні на диску (`notify`), щоб редагування в іншому редакторі чи AI-агентом одразу було видно.

### Навігація між запитами

- **Cmd+Shift+O** — пошук запиту в поточному файлі за назвою, методом або URL (символи документа).
- **Cmd+T** — те саме по всій робочій теці (`GET users` знаходить усі GET на `/users`).
- **Alt+↑ / Alt+↓** — до попереднього / наступного блоку (на рядок запиту).
- **Breadcrumbs** над редактором: `тека › файл.http › POST Створити користувача`, клік по останньому елементу відкриває список запитів файлу.
- **Згортання** (folding): блок цілком, заголовки, тіло, скрипти. Cmd+K Cmd+0 згортає все до рядків запитів — файл стає змістом.

### Дії над блоком (контекстне меню та палітра команд Cmd+Shift+P)

- Копіювати як cURL; дублювати блок; вставити новий блок з шаблону.
- Перемістити блок вгору / вниз (Cmd+Alt+Shift+↑/↓).
- Форматувати блок (Shift+Alt+F): вирівняти заголовки, переформатувати JSON-тіло.
- Розбити довгий query на рядки та навпаки.
- Винести виділене значення у змінну (файлову або змінну середовища).

## Скрипти та тести (версія 2, відкладено)

**Рішення: скриптування відкладено до другої версії.** У першій версії блоки `< {% %}` і `> {% %}` (та `> ./handler.js`) лише розпізнаються й підсвічуються, щоб файли JetBrains відкривалися без помилок. Виконуватися вони не будуть: запит відправляється без них, а в редакторі та в JSON-виводі CLI і MCP з'являється попередження `scripts_not_supported`. Ланцюжки запитів у першій версії будуються через `{{name.response…}}` і автозапуск залежних запитів. Опис нижче — цільовий дизайн другої версії.

Скрипти у стилі JetBrains дають змогу будувати ланцюжки запитів і тестувати API прямо з файлу. Рушій JavaScript — вбудований `boa_engine` (чистий Rust, без C-залежностей).

```http
### Логін
< {%
  request.variables.set("ts", Date.now().toString());
%}
POST {{baseUrl}}/auth
Content-Type: application/json

{ "user": "anya", "password": "{{password}}" }

> {%
  client.test("Статус 200", () => {
    client.assert(response.status === 200, "Очікувався 200");
  });
  client.global.set("token", response.body.access_token);
%}
```

- `< {% %}` — pre-request скрипт перед рядком запиту; `> {% %}` — response handler після тіла. Зовнішній файл: `> ./handlers/login.js`.
- API: `client.global.get/set/clear`, `client.test`, `client.assert`, `client.log`, `request.variables.set`, `response.status`, `response.headers.valueOf()`, `response.body` (розібраний JSON або рядок), `response.contentType`.
- Обмеження пісочниці: без доступу до файлової системи та мережі, таймаут 2 с, ліміт пам'яті 64 МБ.
- Результати тестів — у вкладці Tests і підсумком (`✓ 3/3`) у рядку стану панелі відповіді. `client.log` — у вкладці Console.
- Запуск усього файлу з підсумком тестів стає основою для CI через CLI (див. розділ про AI і CLI).

## Імпорт cURL з буфера обміну

Будь-яка команда `curl` у буфері перетворюється на блок запиту без ручної правки. Головний сценарій: DevTools → «Copy as cURL» → Cmd+V у файл.

### Три способи запуску

1. **Автоматично при вставці.** Редактор перехоплює Cmd+V; якщо текст після обрізання пробілів починається з ` curl  ` (або ` curl.exe  `) і розбирається без помилок, замість сирого тексту вставляється блок. Вставка всередині існуючого блоку створює новий блок після нього. Вимикається в налаштуваннях; Cmd+Shift+V завжди вставляє сирий текст.
2. **Команда «Вставити cURL з буфера»** (палітра команд, Cmd+Alt+V): працює навіть коли в буфері кілька команд — кожна стає окремим блоком. Детектор доступний і з файлу `.sh`.
3. **Підказка при фокусі вікна.** Якщо під час повернення до програми в буфері нова cURL-команда, знизу з'являється ненав'язлива плашка «У буфері cURL: POST /api/orders — вставити? ↵». Показується один раз на вміст буфера; вимикається в налаштуваннях. Буфер читається лише під час активації вікна, фонового опитування немає.

### Приклад перетворення

```bash
curl 'https://api.example.com/v1/orders?limit=20' \
  -X POST \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer eyJhbGciOi...' \
  -b 'session=abc123' \
  --data-raw '{"sku":"A-1","qty":2}' \
  --compressed
```

```http
### POST /v1/orders
# curl 'https://api.example.com/v1/orders?limit=20' -X POST ... (оригінал згорнуто)
POST https://api.example.com/v1/orders
    ?limit=20
Content-Type: application/json
Authorization: Bearer eyJhbGciOi...
Cookie: session=abc123
Accept-Encoding: gzip, deflate, br

{
  "sku": "A-1",
  "qty": 2
}
```

### Підтримані прапорці

| Прапорець | Результат у блоці |
| --- | --- |
| `-X`, `--request` | Метод |
| URL (позиційний або `--url`) | Рядок запиту; query розбивається на рядки, якщо параметрів більше двох |
| `-H`, `--header` | Заголовки |
| `-d`, `--data`, `--data-raw`, `--data-binary`, `--data-ascii` | Тіло; метод POST, якщо не задано; кілька `-d` з'єднуються `&` |
| `--data-urlencode` | Тіло form-urlencoded з кодуванням |
| `-d @file` | `< ./file` |
| `--json` | Тіло + `Content-Type` і `Accept: application/json` |
| `-F`, `--form` | Multipart із згенерованим boundary; `@file` → `< ./file` |
| `-u`, `--user` | `Authorization: Basic user pass` |
| `-b`, `--cookie` | `Cookie:` |
| `-A`, `-e` | `User-Agent:`, `Referer:` |
| `-G`, `--get` | Дані `-d` переносяться у query |
| `-I`, `--head` | Метод HEAD |
| `-L` / без `-L` | Без `-L` додається `# @no-redirect` (точність поведінки curl; вимикається) |
| `-k`, `--insecure` | `# @insecure` |
| `--compressed` | `Accept-Encoding: gzip, deflate, br` |
| `--http2`, `--http1.1` | Версія в рядку запиту |
| `-m`, `--max-time`; `--connect-timeout` | `# @timeout`, `# @connection-timeout` |
| `-s`, `-v`, `-i`, `-o`, `--location-trusted` тощо | Ігноруються; `-o file` → `>> file` |

Невідомі прапорці не ламають імпорт: вони перелічуються в коментарі `# проігноровано: --foo`.

### Розбір командного рядка

- Токенізація за правилами POSIX shell (крейт `shell-words`) + розширення: `$'…'` (bash ANSI-C, Chrome використовує його для тіл з екрануванням).
- Переноси рядків: `\` (bash), `^` (Windows cmd — формат «Copy as cURL (cmd)»), бектік `` ` `` (PowerShell).
- Тіло: якщо це валідний JSON — форматується; form-дані розбиваються на рядки `&`.
- Шумні заголовки браузера (`sec-ch-ua*`, `sec-fetch-*`, `priority`) за замовчуванням видаляються; список налаштовується.

### Розумна підстановка змінних

- Якщо хост URL збігається зі значенням `baseUrl` / `host` у активному середовищі чи файлі, він замінюється на `{{baseUrl}}`.
- Токени в `Authorization` і cookies, що збігаються зі значенням змінної, теж замінюються; інакше клієнт пропонує quick fix «Винести токен у приватне середовище», щоб секрет не потрапив у git.
- Усі заміни відкочуються одним Cmd+Z (спершу відкочуються заміни, другим — сама конвертація до сирого тексту).

### У зворотний бік

«Копіювати як cURL» (Cmd+Shift+C на блоці) генерує команду з уже підставленими змінними; варіант «без підстановки» лишає `{{…}}`. Кругова конвертація `curl → блок → curl` покрита тестами на наборі команд з Chrome, Firefox, Safari та Postman.

## Керування AI-агентом: MCP і CLI

Один бінарник працює в трьох режимах: GUI, CLI і MCP-сервер. Усі три використовують одне ядро (парсер, змінні, виконавець), тож агент отримує рівно той самий результат, що й людина в редакторі. Застосунок називається Respite, бінарник — `respite`.

### CLI

| Команда | Дія |
| --- | --- |
| `respite` або `respite open [шлях[:рядок]]` | Відкрити GUI (у вже запущеному вікні, якщо є) |
| `respite list <файл\|тека>` | Список запитів: файл, рядок, ім'я, метод, URL |
| `respite show <файл> <запит> [--resolved]` | Текст блоку; з `--resolved` — після підстановки змінних |
| `respite run <файл> [запит…]` | Виконати запит(и) або весь файл |
| `respite import-curl [--clipboard] [--to файл]` | cURL зі stdin або буфера → блок (у stdout або дописати в файл) |
| `respite export-curl <файл> <запит>` | Блок → команда cURL |
| `respite check <файл\|тека>` | Діагностика без виконання (для pre-commit) |
| `respite fmt <файл…> [--check]` | Форматування |
| `respite env list` / `respite env show <ім'я>` | Середовища і змінні (секрети масковані) |
| `respite history [--last N]` | Історія виконань |
| `respite mcp [--attach]` | Запустити MCP-сервер на stdio |

Запит адресується ім'ям (`login`), номером рядка (`:42`) або порядковим номером (`#3`).

Спільні прапорці `run`:

- `--env dev`, `--var key=value` (перекриває будь-який рівень), `--env-file шлях`.
- `--output human|json|jsonl|junit` — `human` у терміналі, `json` у пайпі (автовизначення TTY).
- `--include headers,body,timing`, `--max-body 64KB` (агенту не потрібне тіло на 10 МБ), `--jsonpath '$.items[*].id'`.
- `--fail-fast`, `--dry-run` (показати розв'язаний запит, не відправляти), `--non-interactive` (prompt-змінні без значення → помилка, а не зависання).

Коди виходу: `0` — усе виконано і тести пройдено; `1` — провалені тести; `2` — помилка мережі або таймаут; `3` — помилка розбору чи невизначена змінна; `4` — відхилено політикою безпеки. Статус 4xx/5xx сам по собі не помилка (як у curl), якщо не задано `--fail-on-status`.

### Формат JSON-виводу (стабільна схема з версією)

```json
{
  "schema": "respite.run/v1",
  "file": "api/users.http",
  "request": { "name": "createUser", "line": 12, "method": "POST",
               "url": "https://api.example.com/v1/users", "headers": { "Authorization": "••••" } },
  "response": { "status": 201, "reason": "Created", "http_version": "HTTP/2",
                "headers": { "content-type": "application/json" },
                "body": { "id": "7f3c…" }, "body_truncated": false, "size_bytes": 214 },
  "timing_ms": { "dns": 3, "connect": 18, "tls": 22, "ttfb": 95, "total": 142 },
  "tests": [ { "name": "Статус 201", "passed": true } ],
  "history_id": "2026-11-11T20-31-07Z-createUser"
}
```

Помилки мають однакову форму `{"error":{"code":"undefined_variable","message":…,"file":…,"line":…,"hint":…}}`, щоб агент міг сам виправити файл.

### MCP-сервер

`respite mcp` — сервер [Model Context Protocol](https://modelcontextprotocol.io) на stdio, реалізований на офіційному Rust SDK (`rmcp`). Коренем робочої теки є cwd або `--root`; файли поза ним недоступні. Підключення до Claude Code, Zed, Cursor тощо:

```json
{ "mcpServers": { "respite": { "command": "respite", "args": ["mcp", "--root", "."] } } }
```

**Інструменти (tools)**

| Інструмент | Параметри | Повертає |
| --- | --- | --- |
| `list_requests` | `path?`, `query?` | Запити: файл, рядок, ім'я, метод, URL |
| `get_request` | `file`, `request`, `resolved?` | Текст блоку + розв'язані змінні з джерелами |
| `run_request` | `file`, `request`, `env?`, `vars?`, `max_body?`, `jsonpath?` | Результат у схемі `respite.run/v1` |
| `run_file` | `file`, `env?`, `fail_fast?` | Підсумок + результат кожного запиту |
| `send_adhoc` | `http_text`, `env?` | Виконати блок, не зберігаючи його у файл |
| `add_request` | `file`, `http_text`, `after?` | Додати блок (спершу парситься; невалідний відхиляється з діагностикою) |
| `update_request` | `file`, `request`, `http_text` | Замінити блок цілком, решта файлу недоторкана |
| `import_curl` | `curl`, `file?`, `name?` | Блок (і дописати в файл, якщо задано) |
| `export_curl` | `file`, `request`, `resolved?` | Команда cURL |
| `check` | `path` | Діагностика |
| `list_environments` / `select_environment` | `name?` | Середовища і змінні (секрети масковані) |
| `get_history` / `get_response` | `request?`, `limit?` / `history_id` | Минулі виконання та повна відповідь |
| `reveal_in_editor` | `file`, `request` | Лише з `--attach`: показати запит і відповідь у відкритому GUI |

У кожного інструмента є анотації MCP: `readOnlyHint` для `list_*`, `get_*`, `check`; `destructiveHint` для `update_request`. Клієнт може дозволяти перші автоматично.

**Ресурси (resources):** кожен файл `.http` доступний як `respite://file/<шлях>`, остання відповідь запиту — як `respite://response/<файл>/<запит>`, а довідка з синтаксису `.http` — як `respite://docs/syntax` (щоб агент писав валідні блоки).

**Промпти (prompts):** `write_request` (опис → блок за конвенціями файлу), `debug_failure` (запит + відповідь + діагностика).

### Режими: headless і attach

- **Headless** (за замовчуванням) — сервер працює сам, GUI не потрібен. Зміни файлів, зроблені агентом, GUI побачить через спостереження за файлами.
- **Attach** (`--attach`) — сервер під'єднується до запущеного GUI через локальний сокет (Unix socket / named pipe, лише для поточного користувача). Запити агента виконуються в GUI: відповіді з'являються в правій панелі з позначкою «AI», діляться сесійні змінні, cookie jar і вибране середовище. Якщо GUI не запущено, сервер автоматично працює як headless.

### Безпека для агентів

- **Секрети не виходять до моделі.** Значення з приватних файлів середовищ (`*.private.json`), `$dotenv`, `$processEnv` і чутливі заголовки в усіх відповідях MCP і `--output json` маскуються. Агент пише `{{token}}`, підстановка відбувається лише в ядрі.
- **Політика в `.respite/agent.toml`:** список дозволених хостів, дозволені методи по середовищах (напр. на `prod` — лише GET/HEAD), дозвіл на запис у файли, ліміт запитів за хвилину. Порушення → помилка `policy_denied` (код виходу 4).
- **Підтвердження людиною.** Запити з `# @note`, на середовище `prod*` або з `# @prompt` без значення запитують підтвердження через MCP elicitation (або діалог у GUI в режимі attach). Без підтримки elicitation — відмова з поясненням.
- **Журнал дій агента** у історії з позначкою джерела (`gui` / `cli` / `mcp`).

## Архітектура

Cargo workspace із чистим ядром без залежності від GUI: GUI, CLI і MCP — це три тонкі оболонки над одним і тим самим кодом. Так ядро тестується без віконної системи (CI на Linux без дисплея).

### Крейти

| Крейт | Відповідальність | Ключові залежності |
| --- | --- | --- |
| `http-syntax` | Парсер `.http` → AST з позиціями, стійкий до помилок; форматтер; граматика tree-sitter для підсвітки | `tree-sitter`, `logos` або ручний лексер |
| `http-env` | Пошук і злиття середовищ, розв'язання змінних, динамічні змінні, маскування секретів | `serde_json`, `dotenvy`, `uuid`, `jiff` |
| `http-exec` | Виконавець: конвеєр запиту, залежності, кеш відповідей, історія, cookie jar, timing | `reqwest` (rustls, http2, cookies, gzip/br, stream), `tokio`, `jsonpath-rust`, `sxd-xpath` |
| `http-curl` | cURL ↔ блок: токенізація, прапорці, генерація | `shell-words`, `clap` (лише структура прапорців) |
| `http-script` | Пісочниця JS, API `client` / `request` / `response` (фаза 2) | `boa_engine` |
| `workspace` | Робоча тека: індекс файлів і запитів, спостереження, налаштування, політика агента | `notify`, `ignore` (поважає `.gitignore`), `nucleo` (нечіткий пошук) |
| `app` (GUI) | Вікно, бокова панель, редактор, панель відповіді, палітри, сервер attach-сокета | `gpui`, `gpui-component`, `rope` (`ropey`) |
| `cli` | Команди, формати виводу, коди виходу | `clap`, `owo-colors`, `arboard` (буфер) |
| `mcp` | MCP-сервер, клієнт attach-сокета | `rmcp`, `schemars` |

Бінарник `respite` об'єднує `app`, `cli` і `mcp`; GUI підвантажується лише для `respite` / `respite open`, тож CLI стартує за мілісекунди. Опціонально — feature `gui` для збірки headless-бінарника для CI і серверів без віконної системи.

### Редактор у GPUI

- **План A (обрано):** кодовий редактор із `gpui-component` (підсвітка tree-sitter, нумерація рядків, підказки). Автодоповнення і діагностику підключаємо через його провайдери. Першим робимо прототип підсвічування активного блоку.
- **План B (якщо прототип не вдасться):** власний елемент на базі rope + текстової системи GPUI. Дає повний контроль, але це найбільша частина роботи. Щоб перехід був дешевим, виставляємо над редактором власний трейт (буфер, декорації, провайдер доповнень), тож решта GUI від конкретної реалізації не залежить.
- Крейт `editor` зі Zed напряму не використовуємо: він тягне за собою велику частину Zed (project, language, LSP) і ліцензований під GPL.

### Стан і потоки

- Стан застосунку — GPUI `Entity`: `Workspace` (файли, середовище), `Buffer` на кожен відкритий файл (rope + останній AST), `ResponseStore` (відповіді за ключем файл + запит), `History`.
- Парсинг — на фоновому executor GPUI з дебаунсом 30 мс; редактор завжди має останній валідний AST.
- HTTP — `reqwest` потребує tokio, а GPUI має власний executor. Тому в окремому потоці живе tokio-runtime; GUI відправляє задачі через канал і отримує події (`Started`, `Headers`, `BodyChunk`, `Done`, `Failed`) через `cx.spawn`. Скасування — `CancellationToken`.
- Клавіатурні дії — через механізм `actions!` / keymap GPUI, тож гарячі клавіші перевизначаються в `keymap.json` як у Zed.

### Тестування

- Парсер: snapshot-тести (`insta`) на корпусі реальних `.http` файлів із прикладів VS Code і JetBrains + fuzzing (`cargo-fuzz`).
- Виконавець: локальний mock-сервер (`wiremock`).
- cURL: кругові тести на командах з усіх браузерів.
- GUI: `#[gpui::test]` з `TestAppContext` для навігації та дій.
- MCP: інтеграційні тести через клієнт `rmcp` і MCP Inspector.

### Рішення та відкриті питання

- **Цільові ОС для MVP: macOS і Linux.** Windows — пізніше; код не прив'язуємо до POSIX там, де це не потрібно (шляхи, сокет attach через абстракцію).
- **JS-двигун для скриптів: `boa_engine`.** Чистий Rust без C-залежностей, проста збірка під обидві ОС.
- **Редактор: спершу `gpui-component`.** Якщо він не потягне підсвічування активного блоку, пишемо власний елемент. Перша задача фази 1 — прототип для перевірки саме цього.
- **Назва: Respite.** Гра слів: «перепочинок» (rest) і `resp` від response. Бінарник — `respite`.
- **Ліцензія: MIT.** Сумісна з Apache-2.0 у GPUI і `gpui-component`.
- **Розбіжності VS Code і JetBrains: пріоритет за VS Code.** Якщо однаковий синтаксис працює по-різному, беремо поведінку VS Code REST Client. Конструкції JetBrains, які ні з чим не конфліктують (скрипти, `>>`, `@timeout` тощо), підтримуються додатково.
- **Залежні запити запускаються автоматично.** Якщо `{{login.response…}}` ще порожній, `login` виконується спершу без запитання.
- **Історія — у домашній теці: `~/.respite/history/<назва проєкту>/`.** У репозиторій відповіді з токенами не потрапляють.

* **Скриптування (`< {% %}`, `> {% %}`, `client.test`) — у другій версії.** У першій версії блоки скриптів лише парсяться й підсвічуються, але не виконуються; `boa_engine` додається разом із ними.

**Ще відкрито**

1. **Дистрибуція.** macOS: підпис і нотаризація (потрібен Apple Developer ID), Homebrew cask. Linux: AppImage, Flatpak чи .deb/.rpm; Wayland + X11. Автооновлення — так чи ні?
2. **Транспорт MCP.** Лише stdio, чи ще Streamable HTTP на localhost (для агентів, що не запускають процеси)?
3. **Обмеження `boa_engine`.** У скриптах JetBrains є `crypto`, Base64 тощо. Який набір вбудованих функцій дати? Вирішуємо разом із другою версією.
4. **Доступність назви.** На crates.io ім'я `respite` зайняте бібліотекою для протоколу Redis RESP. Пропозиція: крейти з префіксом (`respite-cli`, `respite-core`…), а бінарник лишається `respite` (`cargo install respite-cli`). Вручну ще треба перевірити Homebrew, організацію на GitHub і домен.
